Korrektur der Audio-Features im nativen Kotlin-Code

1. Zufällige Pausen: Bei Playlist-Wiedergabe pausiert ExoPlayer bei Track-Ende über pauseAtEndOfMediaItems und feuert onMediaItemTransition(REASON_AUTO). Der Aufruf wurde dorthin verschoben, sodass der Folgesong nach Ablauf des WakeLock-Timers per player.play() zuverlässig startet.
2. Dynamisches Fade-In: Die Songdauer wird nun mehrfach abgesichert (mediaMetadata.extras, Song.durationMs, player.duration). Die Lautstärke startet strikt bei 0.0f und blendet über die ersten 5% (mindestens 1.0s) sauber und hörbar hoch.

Korrektur-Details Aktiviert
Trigger Pause: onMediaItemTransition (AUTO)
Fortsetzung: player.play() nach delay(ms)
WakeLock: PARTIAL_WAKE_LOCK (safe release)
Fade-In Start: 0% Lautstärke sofort aktiv

01. Nativer Kotlin-Code (ExoPlaybackStateHolder.kt)

Die Listener-Logik wurde präzise an ExoPlayers Playlist-Modell angepasst:

// 1. onMediaItemTransition bei AUTO & REPEAT
if ((reason == AUTO || reason == REPEAT) && randomPause) {
handleRandomPauseBeforeNextTrack(mediaItem)
} else { applyDynamicFadeIn(mediaItem) }
// 2. Fortsetzung nach der Pause mit play()
acquireWakeLock(pauseMs + 5000L)
delay(pauseMs)
player.play() // Startet Track 2!
applyDynamicFadeIn(nextMediaItem)

02. Sichere Lautstärken-Berechnung

Die Track-Dauer wird jetzt aus allen verfügbaren Schichten bezogen:

getCurrentSongDurationMs(mediaItem):
• mediaMetadata.extras.getLong("durationMs")
• mediaItem.song.durationMs
• playbackManager.currentSong.durationMs
• player.duration
→ Kein Lautstärke-Sprung auf 100% mehr bei Start
